Visão geral

O assistente é um app Django que fala com o Keycloak pela Admin REST API, com o admin do realm master. Ele não guarda configuração do Keycloak: lê o estado atual a cada tela e grava direto lá. O único dado próprio é o Histórico.

O que acontece dentro do SSO (aplicação SAML, grupos e claims no portal da Microsoft, do Google ou do Okta) não tem API comum: a etapa 3 entrega as URLs e o roteiro para o time do SSO.

Simular e aplicar

Todas as etapas funcionam igual. O serviço da etapa lê o que existe no Keycloak, compara com o formulário e monta um plano, com um passo por objeto. Simular só mostra o plano. Aplicar executa cada passo na hora em que ele é registrado. Por isso, aplicar de novo dá "Sem mudança" e, se algo falhar no meio, aplicar outra vez continua de onde parou.

Login e permissões

O assistente entra pelo Keycloak como os outros apps: o keycloak.js faz o login no client keycloak-assistente e o Django confere o token. O que o usuário pode fazer vem da role de realm ADMIN.

sequenceDiagram
    autonumber
    actor U as Administrador
    participant A as Assistente
    participant K as Keycloak (KC_REALM)
    U->>A: /login
    A->>K: keycloak.js (PKCE)
    U->>K: usuário e senha (ou SSO)
    K-->>A: token no cookie SSOToken
    A->>A: sso.py confere assinatura, emissor,
client, validade e EMAILS_PERMITIDOS
    alt role ADMIN no token
      A->>A: grupo Admin + superuser: simula e aplica
    else sem a role
      A->>A: grupo Limited: consulta e simula
    end
    A-->>U: /app/

As chamadas à Admin API não usam o token do usuário: usam o admin do master (KEYCLOAK_ADMIN_USER). Por isso o Histórico guarda quem pediu cada mudança.
