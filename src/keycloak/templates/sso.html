2 · No SSO

Microsoft Entra ID
  1. Enterprise applications → New application → Create your own application → Integrate any other application (non-gallery).
  2. Single sign-on → SAML → Basic SAML Configuration: Identifier (Entity ID) e Reply URL com os valores acima.
  3. Attributes & Claims: mantenha emailaddress, givenname, surname e o Unique User Identifier (user.userprincipalname). Em Add a group claim: Groups assigned to the application, Source attribute Cloud-only group display names, marque Customize the name of the group claim com Name groups e Namespace vazio, e deixe Emit groups as role claims desmarcado.
  4. Groups → New group: um grupo de segurança (Security) por perfil, com o nome idêntico ao grupo da etapa 2.
  5. Users and groups: atribua só esses grupos (exige Entra ID P1/P2). Em Properties: Assignment required? = Yes.
  6. SAML Certificates: copie a App Federation Metadata Url e cole abaixo.
Google Workspace
  1. Admin console → Apps → Web and mobile apps → Add app → Add custom SAML app.
  2. Em Google Identity Provider details, baixe o IdP metadata (cole o XML abaixo).
  3. Service provider details: ACS URL e Entity ID acima, Name ID format EMAIL, Name ID Basic Information > Primary email.
  4. Attribute mapping: First name → firstName, Last name → lastName, Primary email → email; em Group membership, os grupos do app com App attribute groups.
  5. User access: ative o app só para os grupos ou unidades certas.
Okta, ADFS e outros

Use os valores acima, mande email, firstName e lastName como atributos e pegue a URL (ou o XML) de metadata. No Okta, em Group Attribute Statements: Name groups, filtro Starts with com o prefixo dos grupos.
