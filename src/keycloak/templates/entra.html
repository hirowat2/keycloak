Etapa 3 · SSO corporativo

Configurar o Azure AD (Microsoft Entra ID)

O que fazer no portal do Azure para o login com a conta Microsoft do cliente, com os valores do realm {{ realm|default:"(nenhum realm)" }} já preenchidos. O Azure é o Identity Provider; o Keycloak é o Service Provider. Nada aqui muda o Keycloak: o cadastro é a etapa 3 e os grupos, a etapa 4. Para um app do Azure que já existe (ex.: depois de trocar o host do Keycloak), use Azure AD dos realms.

Texto para o time do Azure

Seus valores

O mesmo da etapa 3. Entra na Reply URL e não muda depois.
Como aparece em Enterprise applications e no My Apps.

Antes de começar

  • Quem faz no Azure precisa ser Application Administrator (ou Cloud Application Administrator) e poder criar grupos (Groups Administrator ou dono dos grupos).
  • Atribuir grupos ao app exige licença Microsoft Entra ID P1 ou P2. Sem ela, só dá para atribuir usuário por usuário.
  • O realm e os grupos já devem existir no Keycloak (etapas 1 e 2): os nomes dos grupos do Azure serão os mesmos.
  • O Azure não precisa acessar o Keycloak pela rede: ele só redireciona o navegador. Mas a URL do Keycloak precisa ser HTTPS.

Precisamos de uma aplicação SAML no Microsoft Entra ID para o login no {{ app }}.

1. Enterprise applications → New application → Create your own application →
   "Integrate any other application (Non-gallery)". Nome: {{ app }}

2. Single sign-on → SAML → Basic SAML Configuration
   Identifier (Entity ID): {{ urls.entity_id }}
   Reply URL (ACS):        {{ urls.acs }}
   Sign on URL:            {{ host }}
   Logout URL (opcional):  {{ urls.logout }}
   SAML Certificates → Signing Option: Sign SAML response and assertion (SHA-256)

3. Attributes & Claims: manter givenname, surname, emailaddress, name e o Unique User Identifier.
   Add a group claim:
   - Groups assigned to the application
   - Source attribute: Cloud-only group display names
   - Customize the name of the group claim: Name "groups", Namespace vazio
   - Emit groups as role claims: desmarcado
